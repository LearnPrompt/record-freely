# 从真实修订到可靠交付

本清单归纳一次长片打码和另外四条素材的独立复查；事实、覆盖和版本见 [四条脱敏案例](../docs/case-lessons-v1.1.md)。流程借鉴黄白的 [guoshen](https://github.com/huangbai-AI/guoshen)，按放心录的本地实现整理，未复制 guoshen 代码或平台规则库。新增第五条素材见 [v1.2 案例](../docs/case-lessons-v1.2.md)。以下是 Agent 指导；v1.2.0 提供显式审阅的 [局部算法入口](../docs/local-mask-algorithms.md) 与 [查看器](../docs/review-viewer.md)，不能把每条经验说成自动功能。

## 先分清要解决的问题

| 问题 | 决定依据 | 最小处理 |
| --- | --- | --- |
| 明确的网址或联系方式残留 | 原生画面、用户遮挡范围、准确位置 | 局部补遮，保留普通文本 |
| 用户担心平台误识别文件路径 | 用户偏好，不是已证实的平台规则 | 确认保留策略，再按精确字符边界遮父路径；可只留末个 `/` 后的文件名 |
| 用户要保留作者与 Skill 名 | 原生画面的组件及分隔符 | 保留确认的作者／Skill 后缀；不能只按字符串长度推矩形 |
| 用户要遮“其他平台” | 上下文或用户明确含义 | 发布平台词与工具、模型、厂商品牌分开；点名标题位置不扩到全片品牌 |
| 事实、价格、功能状态或效果表述待核 | 原始来源、条件、实际执行与反证 | 核查、补说明或重录；遮错字／错误状态不能证明内容正确 |
| AI 片段或第三方素材 | 已有标识、实际生成来源与许可 | 补可读标签／核权利；遮工具名、作者名或水印不能代替标识或授权 |
| 平台给出通用提示 | 实际通知及其范围 | 记录观察；具体原因未知时保持 `confirmed_reason: null` |

低流量、出现国外 AI、美元、工具名、文件扩展名或跨平台字样，均不能自动变成拒审原因。实际平台和场景仍按 [发布前流程](../docs/prepublication-review.md) 查现行官方依据。个人严格偏好单独记录，不进入通用禁词库。

## 最小遮挡也要保护观看

先确认“应盖住什么”和“应留下什么”。一处待核实的事实不授权 Agent 用整页遮罩、重做动画、遮人物或消除整段字幕。曾被用户退回的整页替换应保留为失败案例，不能因为解码通过便宣传成成功修复。

文件名、目录用途、Skill 后缀、正常字幕、工具功能与讲解动画都是保留对象。用户希望遮更多时按其确认范围处理；需要扩大编辑范围时，把具体拟修改内容给用户审阅。局部背景色填充也属于打码，但不能因此把整片背景处理都列为隐私修复点。

用户明确要求“文件路径只留最后一级”时，要检查真实绝对路径和相对路径：例如 `feeds/follow/example.opml` 仍应遮 `feeds/follow/`，只留 `example.opml`。自动入口的 `identity_path` 父目录策略只覆盖其可识别的身份路径，不能冒充所有文件路径检测；其余已确认路径由 Agent 精确补录。普通命名空间、品牌、数学除号和斜杠命令（如 `/help`、`/queue`）不当成文件路径；GitHub 作者／Skill 前缀等用户明示保留项按例外记录。不能只以用户名消失判定严格父目录范围已完成。

## 遮挡需要覆盖完整生命周期

1. 用检测点定位，再逐帧确认首次出现、最后出现和邻帧；抽样时间只是线索，不能直接当遮罩首末帧。
2. 同一地址可能在顶部、侧栏、代码、悬浮提示、缩小的画中画或页面嵌图重新出现。旧框内部没有漏字，仍可能在框外或旧结束时间后可读。
3. 检查换行尾段、路径尾行、UUID 尾巴、滚动裁切残字、选中高亮、低对比小字和字幕交叉。完整 OCR 执行成功不表示这些全部被召回。
4. OCR 语言优先级会改变漏检；结合局部 OCR、原生裁片和模板证据纠正。模板匹配也会误报，不能把相似标签都算新漏码。
5. 静止段使用覆盖已观测框的固定包络；运动框平滑后仍须覆盖当前检测框。切镜和缺失帧断开，不跨无证据帧填充。稳框后应用人工补丁，再核对补丁首末帧与保留文本。
6. 若原生字形确实连续显示但 OCR 间歇命中，用真实像素证据确定连续边界；不能仅为减少闪烁任意延长遮罩。

匿名报告保存类别、帧、矩形、决定与原因，不保存完整私有文字。候选条数、矩形检查次数与独立敏感事件数不同，应分别计数。编号与普通文字可能误拼成域名；文件扩展名及模型／标签须按上下文复核。

## 声音和字幕是独立证据

可执行的完整 PCM 信号检查、指定语言补检查和私有首遍诊断留存见 [音频示例](../docs/audio-review-examples.md)。

有音轨不等于有声音。先看完整解码的信号证据：数字静音可以确认 PCM 峰值为零；低音量、噪声或只看几个样本不能替代完整检查。静音上的重复 ASR 结果应排除，诊断材料留在私有目录，不引用为真实口播。

中文首遍转写可能漏掉英文对白。补转写须记录语言、实际源区间和加回原片的时间偏移；不能把片段的零秒放到视频开头。原始结果保留以解释修订，错识别工具名须与实际声音／画面核对。音轨未修改是编辑状态，不是“口播确实出现了某词”的内容证据。

硬字幕、外置 SRT、转写和画面分别说明覆盖。音轨相同可在解码 PCM 哈希等证据支持下复用旧 ASR，并记录依据；剪切或改音轨后不能默默沿用旧时间轴。ASR 检索通过不等于人工逐字试听或音乐版权核实。

## 从原片重建，避免累积压缩

把已经确认的自动遮罩、稳定框和人工补丁合并到同一源片坐标，再一次叠加后编码。旧成片用于定位和对比；继续叠加再编码会累计压缩，长片实测曾降低整幅画面的文字、人物和背景清晰度。

一次长片修复采用原片 4K30、H.264 `CRF 16`、`preset medium`、BT.709、AAC 192 kbps，不添加降噪、锐化或缩放。该参数是已验收素材的配方，不是所有素材或 HDR 的默认保证。通用自动/refine 入口现在可显式指定 `--crf 16 --preset medium --color-space bt709`；默认仍为 CRF18/fast。先比较代表性一分钟 SDR 样片，再用同一配方重建全片。分段编码后以视频包复制拼接，应另查拼接点、PTS 和音画同步。

可信字幕／文字图层来自干净且已确认的资产。不能从当前帧按白色、橙色或其他颜色恢复原像素；这可能把私有文字恢复出来。图层覆盖、透明边界和交叉字幕也要验收。README 标题的一个字母多挡，同样属于需要修的保留内容。

重建旧配方时逐层核对内容与绘制顺序：先画新遮罩，随后叠加的旧恢复层仍可能重新画回父路径。仅在末尾追加干净字形不够，其透明区域不会擦掉旧层。发现污染时删除或替换对应恢复层，保留独立干净标题及文件名，并复核完整交叉时段的首末与邻帧；资产 SHA 正确不能证明图层内容干净。浏览器 seek 画面需和原生相邻帧对齐，不能用某一张正确预览代表整个生命周期。

保留内容也要按完整生命周期验收，并与原片比对。新补丁保住一段 README 的 R，不代表更早的旧框也已修正；`EADME.md`、`pdate_news.py` 仍可能被 OCR 当作普通文件名，不产生隐私候选。检查每行首次、最后、滚动和字幕交叉帧，同时确认父目录已遮、末斜杠不露、首字母与完整 basename 可读。不要只验收新加的遮罩；原有确认框也可能覆盖文件名首字母。

严格父目录任务先从原片盘点全部实际路径对象，分别登记输入行、执行回显、滚动历史与推理文字中的出现区间。用户名已被遮挡的成片可能不再触发身份路径检测，仍须检查剩下的目录词和斜杠。逐个对象核完整首末、邻帧及字幕交叉；某一条命令的首次出现不能代表同目录的全部副本。原片清单用于定位，最终编码文件仍须独立复扫并绑定新 SHA。

字幕入场时的字距、位置和透明度可能逐帧变化，静止标题图层不能直接覆盖动画帧。需要保护交叉字形时，从独立干净资产定位实际相交的字形，逐帧核对注册位置及透明度；无法可靠匹配则保持待审。相邻帧也要复核，不能由一帧正确就延长同一补丁。

编码前未处理区域可验证与原片逐像素一致；编码后 H.264 是有损的，不能宣称全帧像素仍相等。灰块的编码后 RGB 变化不等于漏码；应看解码画面是否仍能读到敏感字、边缘是否漏字及保留区域是否清楚。

## 版本、时间和查看器一起交付

记录唯一输入／输出版本、完整 SHA、代码提交、源帧与成片帧数。原片不改，旧版本保留。删除区间采用半开区间 `[start, end)`，保存源到成片映射；删除之后的导航时间不能直接抄源时间。

CFR 的真实整数帧数及解码 EOF 应核对，容器六位小数时长乘帧率再 `ceil` 可能多出一帧。VFR／未知帧数需按实际时间戳和解码记录处理，不能以 CFR 整数规律推断。抽帧滤镜重初始化曾造成时间轴重置；相关失败产物应排除，替代提取后核验实际帧对应、严格递增时间戳与最后时间点，不能以文件序号当源时间。

直接用 [实际打码时间轴](../docs/actual-mask-timeline.md) 中的 `scripts/build_review_timeline.py` 导出审录事件，再由查看器导航。时间轴工具不检测内容、不剪片；本地播放器由 `scripts/serve_review.py` 提供。快速复查默认导航到实际局部打码区间：仅合并重叠或相接区间，不跨无打码空档，不跨删除段；很长的区间提供缩放、换行等内部检查点。按类别筛选时按该类别重建区间。正常字幕、背景样式、导航保护、AI 标识、保留项和裁切可另列，不能把整片样式变成逐分钟修改清单。

播放器至少验证首、中、尾、缩放重点及裁切后的实际可见画面。加载到时长、`readyState`、`currentTime` 正确或视频全文件解码通过，都不能替代浏览器里看到目标帧。本地 HTTP 服务需支持 Range，否则即使首帧可见也可能不能 seek；黑屏可先修显示或解码帧绘制，不用为查看器重新压缩成片。

## 检查覆盖、成本和失败如实记

- 每版成片复扫绑定其自己的 SHA；旧版全帧 OCR 不能写成新版全帧检查。
- 抽样帧、归一化 CFR 帧、全部原始编码帧、人工看过的帧与矩形检查次数分别记录。全帧 OCR 不等于逐帧视觉理解；失败零帧也不等于召回百分之百。
- 任务编码尝试次数与交付文件累计编码代数分开。重新从原片做第二次尝试，成品仍可是一代编码，但任务确实重试过。
- 音频复制、音频重新编码与视频编码分开记录；数据包复制不增加视频编码代数。
- 本地 FFmpeg／Vision／OpenCV／Whisper 未调用付费媒体 API，不表示 Codex 对话额度为零。没有实际同口径用量及对照，不写节省百分比。
- 阶段累计耗时、并行墙钟耗时、失败尝试及验收时间分开，注明素材、机器与覆盖。一次实测速度不推广为通用承诺。

最终交付应能回答：修改从哪版／哪份原片开始；局部敏感内容盖住了吗；正常内容留下了吗；实际检查了哪些帧和音轨；还有哪些未知；是否真的投稿。公开材料只放脱敏经验、代码和可公开的合成例子，完整私有证据仍随授权的本地复查包交付。

## 同色遮罩与移动屏幕：逐物体审阅

取色、渐变和双人胸牌的执行边界见 [背景色遮罩](background-colour-masks.md)。多边形光流使用人工确认的原片锚点，失跟、切镜、离画及低置信度段保持待审；不能为视觉连续性隐填未知轨迹。底色从同物体干净邻域取样，皮肤、玩偶、字幕、反光和其他敏感区域排除。渐变拟合有限且限制斜率；样本不足时停止并说明，不自动改成大块灰色。

透明 Logo 必须同时检查内部镂空和外部透明：先用审阅的清字框盖掉底词，再叠加可信图层；两者的编辑区域都记录。采访修订和个人体验删改是同一素材的不同分支，不能混用帧数、音轨验证或复扫成绩。

独立复扫首轮失败时保留原报告，按实际失败帧补跑，并以唯一帧去重统计最终覆盖、已恢复失败与未检查帧。普通字幕误识别为号码要看原生画面；候选为空不等于平台已接受。
