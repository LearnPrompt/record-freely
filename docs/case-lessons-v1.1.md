# 从能打码，到能放心交付：四条素材的修订经验

LearnPrompt 希望把“看见 → 学会 → 做成”落实在创作者的工作里：录制时专注讲清内容，录完由 Agent 整理真实证据、修正局部暴露并给出可快速复查的成片。我们仍需要创作者判断保留范围、核对内容和确认发布；工具的工作是让这些决定有迹可查。

本次从两个相关复查对话中归并出 **四条独立素材**。同一长片的 v3 预检与 v6 重建、同一短片的多轮修订均只算一条；不能把重复对话或版本数当作更多成功案例。下面是脱敏事实与工程学习，不包含私人地址、原始 OCR／ASR、原片或工作截图。

流程借鉴黄白的 [过审 guoshen](https://github.com/huangbai-AI/guoshen) 对证据、候选、语境、反证和真实反馈的区分，按放心录的架构整理；未复制 guoshen 的代码或平台规则库。本篇的经验记录和 Agent 指导不等于每项已成为自动脚本功能。详细执行方法见 [经验清单](../references/review-lessons.md) 与 [发布前流程](prepublication-review.md)。

## 案例一：长片的漏码、抖动与画质

长片预检确认了文档网址和邮箱残留，也提出 AI 演示标签、下载工具目录、代理／额度卡片和第三方素材的待核查项。这些不同问题不能全部称为已证实的卡审原因：用户收到的是通用提示，`confirmed_reason` 仍为 `null`。普通工具名、美元、文件路径、影片长短没有因此变成通用禁词。

用户多次回看后，要求保留作者／Skill 名、普通目录和字幕，纠正过挡；后来又选择更保守的路径策略，只留最后一个 `/` 后的文件名。我们把它记为本片偏好，而非平台已确认的文件路径规则。缩放、移动、换行尾巴和低对比小字需要在原生画面定边界，不能凭文本长度推框或只检查已有码块内部。

多轮在成片上处理后，用户发现整幅画面变软。最终按已认可的一分钟样片方案，从原片合并修订、使用可信干净字幕图层、一次编码重建；保留 4K30，采用 H.264 CRF16 / medium / BT.709 与 AAC 192 kbps，不做降噪、锐化和额外缩放。旧版只作定位／对比，不再作渲染底片；README 标题字母过挡也一并修正。该长片配方是素材验收记录，不是通用脚本自动支持全部复杂图层的承诺。

交付长片包含 63,673 帧；从源片删除 198 帧后建立源／成片映射。完整解码、时间戳、拼接点与音画同步检查，和局部隐私覆盖、原生画质比较分别记录。编码前修改区域外像素一致不等于编码后有损视频无损。本地完整复查包保留了原片、源文件、各版证据及验证材料；其私有媒体不会因发布 Skill 而公开。

快速检查器初版按每分钟或固定间隔导航，未贴合创作者需求。改版依据实际局部打码事件生成 **194 个连续区间**，剔除全局样式和正常文字恢复，长区间内补缩放等检查点；分类后重新计算对应区间，切除后的成片时间也校准。后台颜色融合的局部隐私遮罩仍算打码，整片背景样式则不应成为导航点。区间与匿名记录数量不是独立链接数量。

## 案例二：静音手机录屏不能拿 ASR 幻觉当口播

素材实际含音轨，但完整解码 PCM 峰值为零，为数字静音。Whisper 生成了重复句子；这些文字被排除，原始结果只在私有诊断材料保留。这里的学习是“先验证信号，再使用转写”，不是“所有低音量音频都跳过”。

画面里的新闻汇总来源数量，不能替代具体出处、日期和数字口径；AI 解释也不能通过重复站内摘要证明新增因果。价格展示需要单位、输入／输出、适用档位与核验日期。公共案例不固定历史模型价格，以免把会变化的事实变成永久规则。页面按钮、登录功能和手机状态标识只是线索，需结合实际语境；录屏尾段可以按编辑需要收尾，不能称为已经证明的禁发项。

本片仅有预检建议，没有实际编辑或投稿结果。不能从采样未发现私人联系信息推导逐帧零泄漏。

## 案例三：多语言对白、AI 标签与“完成”表述

中文首遍转写漏掉英文对白，后续按真实片段补英文与中文识别，并加回源片时间起点。初次结果保留，工具名错字不当作真实发言。分段零秒不是整片零秒，跨语言补识别的覆盖也须独立记录。

口播已说明 AI，不代表所有观众都能看懂哪一部分是生成内容。生成画面／真人原始表演需清楚区分，发布页声明另核；不编造固定“前五秒”规则。录屏里的“未验证／待插入”与“全部素材已完成”冲突，应补齐并重录或准确说明模板状态，不能仅删占位字样。演示入口应与所说步骤一致；个人一次成功保留条件，不能推广为任意素材的一次保证。第三方角色或素材许可未知时继续待核，遮作者名不能产生授权。

本片仅预检；事实准确、可复现入口、生成标识和权利都是分开的待办，不能统称为平台已经命中的问题。

## 案例四：少挡一点，比整页改掉更有用

小程序教程里，模拟检查、手机试用、正式上线和授权状态需要分开；画面出现未授权不能证明现版仍不可用，也不能靠遮掉错误把功能包装为可用。应展示实际授权、读回或准确说明历史状态。真实案例速度和个人审核经历保留条件，不写成普遍时间保证。

一次整页卡片覆盖了操作动画、人物和字幕，虽然技术解码通过，创作者退回了这一方案。这是助手编辑判断错误，放心录与过审都没有要求这样处理。后续从原片恢复主体，仅合并已确认的局部地址／路径和用户点名的发布词遮挡；用户选择保留的表述也保留。不确定新闻事实移到核查／配文建议，不再用整页替换处理。

用户的“其他平台”指发布平台词，不能扩大为所有工具和模型品牌；点名标题中的标识仅在该位置处理。低对比字形在源画面连续显示，OCR 却只有少量命中；首轮编码后的独立复扫发现遗漏，之后按真实像素生命周期补齐，从原片重做。交付视频为一代编码，任务编码尝试实际为两次，两者均记录。

早期版本完整 OCR 的证据仍保留，但最终输出绑定的是 884 帧重点／分布检查及完整解码，不能冒称全帧视觉通过。缩小嵌图、页脚重现、换行尾段、滚动裁切残字都需查首末帧；模板相似误报与真正遗漏也分开计数。灰块的编码后颜色不恒等于原 RGB，验收应看可读性、边缘和保留内容。

短片查看器曾显示正确时长与进度，却实际黑屏。修复显示后，在真实浏览器查看首、中、尾的解码帧，未重编码视频。它促成了新的验收要求：点击跳转后必须看见对应画面，而不止检验媒体元数据。

## 本版本如何收录，哪些仍未证明

经验进入 [Skill 入口](../SKILL.md)、[Agent 清单](../references/review-lessons.md)、[发布前流程](prepublication-review.md) 和 [私有记录模板](../references/platform-review-template.json)。模板补了版本／编码、静音与语言偏移、源／成片映射、实际可见帧等记录位；填空模板本身不执行检查。

本地 OCR、跟踪、补丁、FFmpeg 与已有本地语音模型处理，没有付费媒体 API 的费用；Codex 对话仍消耗额度。现有记录缺少完整同口径 Codex 实际用量及基线，因此不发布节省百分比。耗时按实际阶段、并行方式和重试范围记，不能把阶段累计时间当创作者等待时间或宣传通用速度。

这四条素材没有产生平台真实过审的验证记录。长期可复用的是保留证据、少挡内容、从原片生成、检查最终文件、可快速回看以及如实记录未知；后续若取得具体平台反馈，应追加脱敏观察与证据，不把单次结果自动升级为通用规则。
