# 独立 Agent 复查

这是正式包装阶段的历史复查，不是新增一分钟真实样片的试用结论。远端查看[公开证据入口](public-review.md)；下列 `review-run/` 和完整数据集路径指本机历史归档。

结论：**源码运行与发布候选通过，发现的一个 P2 已修复并独立复验**。完整交接资料的原片、work/、outputs/ 与旧 Skill 快照已逐文件重算 SHA；正式包最终快照、复查产物收集与 ZIP 的封装由交付流程继续完成，本报告不把这项待封装工作当作已公开发布。

复查不是引用作者验收结论：我读取了 Skill、Swift/Python、测试、三语 README、About、指标及交接说明，在 `release/review-run/` 新建素材运行实际 macOS OCR、FFmpeg 导出、稳框与人工矩形修订，并查看解码后的画面。

## 发现与整改

**R1 / P2：尺寸和修改时间不能绑定原片内容。** 修复前 `scripts/redact_video.py:311` 只记录 size/mtime，`scripts/refine_video.py:103–105` 只核对这两项。复现用另一段黑屏视频，补尾部零字节至源片同样 127,872 字节，再设置相同 mtime；refine 把错误视频套入原报告，返回 complete。

复现输入与错误结果保留在 `../../review-run/independent-fixture/unrelated.mp4`、`wrong-source-accepted/`，没有删除不利证据。最小必要修正是将原片完整 SHA-256 加入自动报告，并在 refine 探测和创建输出前核对。当前实现已完成此修正。我用新生成的合法 SHA 报告重新给无关片测试：明确拒绝，输出目录未创建；字节相同但改了文件名和 mtime 的副本可正常处理；缺 SHA 的旧报告也拒绝。核验记录为 `wrong-source-fixed-check.json`。

## 结论的范围

合成素材通过不等于任意视频零漏码。我独立重取了三处共六张真实对照，以及 09:00 顶部裁切；原案例的 63,871 帧全片解码、73 点原生像素验证检查了方法和记录，没有在本轮重新整片解码一次。

便携引擎不会自动判断作者名或身份路径的业务含义；案例的后缀保留、章节图层与精细 GOP 修补属于人工复验成果。新入口音频重新编码，不能套用案例的原 AAC 包一致指标。旧反馈 25:41 `.html` 仍未定位，文档已披露。

Codex 项目额度消耗和节省量目前无法证明。父线程 token 有精确来源，但不含子 Agent 总量、不是账单、包装尚进行中；不会由零云端 OCR API 或缓存 token 推出零额度、节省百分比或全片几十分钟完成。正式公开前仍需真正完成仓库/下载位置上传并验证；本报告确认本地成果，不确认公开发布。
