# 中文发布文案 · 发布前核验附件

## 可直接复制的正文

录教程时，我以前总有一个小动作：看到链接、终端路径，就先停一下。这个会不会被当成引流？这块要不要重新录？

最近在做影视飓风相关的剪辑工作流教程，干脆把这件事交给了 Agent。

我给它一段 35 分 29 秒的 4K 录屏。第一次，能盖住地址，但它也会挡住 Skill 名字，灰框会抖，鼠标一高亮还会漏掉一行。

于是我们拿真实帧一处处改：链接留下作者和 Skill 名；文件路径只收起个人身份前缀；画面停住，框就停住；画面放大、滚动，框再跟着走。前后对比放在图里，做了什么一眼就能看出来。

首个 5 分钟片段的自动初稿跑了 13 分 56 秒。后面的人工反馈、修订和整片验收另算。处理用的是本机 Vision OCR、OpenCV 和 FFmpeg，没有逐帧调用云端视觉模型。Agent 本身会消耗 Codex 额度；能查到的 token 和耗时记录一起放出来，没有测出的“省了多少额度”就不编。

现在把它打包成了一个 Skill：**放心录 · Record Freely**。

我的想法很简单：你应该先把想说的事情录下来。至少今天，录屏里那些可能被看成引流的地址，Agent 已经能帮你整理、缩小遮挡、修正漏码，再交出能检查的成片。平台最终如何判断仍由平台决定，但这件麻烦已经有了可以反复调用的工具。

这是 LearnPrompt 的又一次“看见 → 学会 → 做成”。中英日 README、实现、测试、前后对比、成本与耗时证据都在。另一位 Agent 可以直接在 GitHub 看源码和证据，或者只取一分钟的真实 4K 样片实跑。原片和全部中间文件仍保留在本机完整复查包；公开全文件清单，不要求另一台电脑先腾出 68.5 GB。

## 短版

录教程时遇到链接、个人路径，先别急着重录。

我让 Agent 修了一条 35 分 29 秒的 4K 录屏：留下 Skill 的作者和名字，只遮路径里的身份前缀，再把抖动和漏码逐帧修好。

现在把它做成了 **放心录 · Record Freely**。本机 OCR + 跟踪 + FFmpeg，附中英日说明、真实前后对比、公开复查证据和全文件清单。先把内容录下来，剩下的交给 Agent 一起完善。
